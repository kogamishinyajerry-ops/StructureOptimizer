# StructureOptimizer PRD v0.1

日期：2026-05-12  
状态：第一版产品定义  
来源：`research/industrial-structural-optimization-report.md`

## 1. 产品定位

StructureOptimizer v0.1 是一个面向结构工程师和研发开发者的结构优化可信工作台。第一版不追求替代商业 CAD/CAE 平台，而是用标准化基准问题证明一条可复现的优化闭环：

1. 定义结构优化问题。
2. 运行 2D/简化 3D SIMP 拓扑优化。
3. 输出候选结构、收敛历史和指标。
4. 对候选结构执行独立验证。
5. 生成可审计的优化报告。

核心价值不是“自动画出漂亮形状”，而是“生成可复核的轻量化候选，并把优化前后证据保存下来”。

## 2. 目标用户

主要用户：

- 结构/CAE 工程师：需要快速验证轻量化方向、载荷路径和体积分数约束。
- 机械产品研发人员：需要在早期概念阶段比较多个结构候选。
- 自研仿真/优化工具开发者：需要一个清晰、可扩展、可测试的结构优化基线。

暂不服务：

- 需要完整商业 CAD 内核和复杂装配处理的企业 PLM 用户。
- 需要非线性接触、疲劳寿命、复合材料铺层、多物理全流程认证的安全关键项目。
- 只需要视觉生成或概念渲染、无需工程验证的用户。

## 3. 第一版目标

v0.1 的目标是跑通“基准库 + SIMP 优化 + 独立验证 + 报告”的最小可信闭环。

必须交付：

- 一组结构优化基准问题。
- 一个统一问题配置格式。
- 一个 2D SIMP 优化器主线。
- 一个简化 3D 扩展接口或样例骨架。
- 一个独立验证流程。
- 一个命令行入口或等价可脚本化入口。
- 一个结构化结果目录。
- 一份自动生成或半自动生成的验证报告。

## 4. 非目标

v0.1 明确不做：

- 完整 CAD 导入、STEP 布尔运算、NURBS 重构。
- 商业求解器适配。
- 云端任务队列、协同、账号、权限、PLM 集成。
- 复杂 GUI。
- 多物理、疲劳、屈曲、非线性接触。
- “AI 自动设计可投产零件”的产品宣称。

## 5. 核心用户流程

### 5.1 运行内置基准

用户选择一个内置基准，例如 `mbb_beam`、`cantilever`、`l_bracket`、`loaded_hook` 或 `simple_bracket`。

系统读取基准配置，建立网格、材料、边界条件、载荷、目标函数和体积分数约束。用户运行优化后，系统生成密度图、收敛曲线、迭代指标和最终候选。

验收标准：

- 用户能用一个命令运行至少一个内置基准。
- 运行结束后有固定目录保存结果。
- 结果目录包含配置快照、迭代历史、最终密度场、图片和指标摘要。

### 5.2 优化候选验证

系统对优化结果执行独立验证。验证流程不能直接复用优化迭代中的临时指标作为最终结论，必须用最终候选重新计算质量、柔度、最大位移和基础应力指标。

验收标准：

- 验证输出包含优化前基线与优化后候选的对比。
- 报告区分“优化迭代指标”和“验证指标”。
- 若验证失败，系统明确标记失败原因。

### 5.3 报告输出

用户运行完成后可以得到一份 Markdown 报告，报告用于复盘和后续工程评审。

报告必须包含：

- 基准名称与配置 hash。
- 材料、网格、载荷、约束、目标、体积分数。
- 优化算法、迭代数、收敛状态。
- 基线指标、优化指标、验证指标。
- 输出文件索引。
- 风险和限制说明。

## 6. 功能范围

### 6.1 基准库

第一版内置基准：

| 基准 | 维度 | 目的 | 必须指标 |
|---|---:|---|---|
| `mbb_beam` | 2D | 验证 SIMP 标准拓扑优化主线 | 柔度、体积分数、迭代收敛 |
| `cantilever` | 2D | 验证载荷路径和边界条件 | 柔度、最大位移、质量 |
| `l_bracket` | 2D | 暴露应力集中和几何敏感性 | 柔度、最大位移、近似应力 |
| `loaded_hook` | 2D | 验证非矩形设计域 | 柔度、体积分数 |
| `simple_bracket` | 简化 3D 或 2.5D | 为后续 3D 扩展留接口 | 质量、最大位移、柔度 |

### 6.2 SIMP 优化

第一版只要求：

- 最小柔度目标。
- 体积分数约束。
- 密度过滤。
- 惩罚因子。
- 迭代收敛条件。
- 固定载荷和线弹性材料。

暂不要求：

- 多材料。
- 多目标 Pareto。
- 鲁棒优化。
- 复杂应力约束优化。
- 大规模 HPC。

### 6.3 结果管理

每次运行必须生成独立目录，例如：

```text
runs/<benchmark>/<timestamp>/
```

结果目录至少包含：

- `input.json`：完整输入配置快照。
- `metrics.csv`：每轮迭代指标。
- `density.npy` 或等价密度场文件。
- `density.png`：最终密度图。
- `convergence.png`：收敛曲线。
- `verification.json`：独立验证结果。
- `report.md`：本次运行报告。

### 6.4 验证闭环

验证闭环必须回答：

- 优化前基线质量是多少。
- 优化后候选质量是多少。
- 优化前后柔度如何变化。
- 优化前后最大位移如何变化。
- 最终候选是否满足体积分数约束。
- 最终候选是否出现明显断连或无效结构。

### 6.5 CLI 或脚本入口

第一版入口建议：

```bash
python -m structure_optimizer run --benchmark mbb_beam
python -m structure_optimizer verify --run runs/mbb_beam/<timestamp>
python -m structure_optimizer report --run runs/mbb_beam/<timestamp>
```

如果项目初期还没有包结构，可以先用等价脚本入口，但命令语义应保持稳定。

## 7. 成功指标

产品层成功指标：

- 新用户能在本地 10 分钟内跑完一个 2D 基准。
- 至少 3 个 2D 基准能稳定收敛并生成报告。
- 每个运行结果都可复现，配置和输出不依赖隐式全局状态。
- 报告明确区分优化结果和验证结果。

工程层成功指标：

- 同一基准、同一配置重复运行，关键指标差异在可解释范围内。
- 无效输入能被拒绝，例如负体积分数、缺失载荷、空边界条件。
- 至少一个测试覆盖输入校验。
- 至少一个测试覆盖完整 run -> verify -> report 流程。

## 8. 风险与约束

主要风险：

- 2D 基准表现好不代表真实 3D 工业零件可直接投产。
- 简化应力指标不能替代工程认证级应力分析。
- 密度场转几何的后处理会改变性能。
- 若配置格式过早复杂化，会拖慢 MVP。

控制方式：

- 文案中坚持“候选”和“验证”，不写“自动保证强度”。
- v0.1 报告固定显示限制说明。
- 数据模型先覆盖必需字段，避免为未来 PLM/云协同过度设计。
- 所有结果必须保留输入配置快照和算法参数。

## 9. 版本路线

v0.1：2D/简化 3D SIMP 基准库 + 验证闭环。  
v0.2：制造约束粗检，例如最小构件尺寸、对称、挤出方向、overhang 近似检查。  
v0.3：外部开源求解器适配，例如 CalculiX、Code_Aster、FEniCS 或 JAX-FEM。  
v0.4：多候选对比、Pareto 视图、批量实验和报告模板。  
v0.5：真实 CAD/mesh 输入的受限工作流。
